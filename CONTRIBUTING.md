# Contributing

HRI is pre-alpha. Contributions should prioritize working, reproducible capabilities and honest limitation reporting.

## Useful early contributions

- Architecture and threat-model review
- Test-corpus design using legally redistributable fixtures
- Parser robustness and malformed-input test plans
- Adapter contracts and dependency/license inventory
- Documentation corrections and reproducible bug reports

## Contribution requirements

- Explain the problem, scope, and expected behavior.
- Include tests for normal, malformed, and boundary inputs.
- Document platform and dependency requirements.
- Do not include credentials, private user data, malware samples, or unlicensed corpora.
- Identify whether behavior is observed, derived, or hypothesized.
- Never claim CI or tests passed unless a successful run is linked.

A contribution does not become supported merely because it compiles. Capability status requires validation evidence.
